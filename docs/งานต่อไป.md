## 1.1 exp ไม่เดินเลยสักหน่วย — ไม่มีระบบไหนเรียก `AddExpForAction`

**หลักฐาน:** `server/Core/Player.Skills.cs:1327` คอมเมนต์ในไฟล์เขียนเองว่า
> *"มีไว้เทสอย่างเดียว เพราะตอนนี้ยังไม่มีระบบไหนเรียก `AddExpForAction` (เก็บของ/คราฟต์/ต่อสู้ อยู่คนละไฟล์ที่ทีมอื่นดูแล)"*

`grep -rn "AddExpForAction" server/Core/` เจอแค่ในไฟล์ที่นิยามมันเอง — ไม่มีผู้เรียกจริงสักจุด
⇒ เล่นทั้งวันเลเวลไม่ขยับ · แต้มสกิลไม่เพิ่ม · ต้นไม้สกิล 918 โหนดเป็นของตาย

**ของที่มีอยู่แล้ว (ไม่ต้องสร้างใหม่):**

| อะไร | ที่ไหน |
|---|---|
| `public void AddExpForAction(int weight, SkillCat? category, string reason)` | `Player.Skills.cs:705` |
| `public void AddExp(int amount, string reason)` | `Player.Skills.cs:672` (ส่ง `ExpGained` + `SendFullStatistics` + `SaveSkillState` ให้เอง) |
| น้ำหนักครบทุกการกระทำ | `SkillTuning` — `GatherWeight=1`(:60) `CraftWeight=2`(:63) `BuildWeight=3`(:66) `KillWeight=3`(:69) `ButcherWeight=2`(:72) |
| `ActionsPerLevel = 40` · `CategoryExpPerAction = 1` | `Player.Skills.cs:81, :90` |
| `using SkillCat = Shared.Skill.Category;` | `Player.Skills.cs:11` |

**สิ่งที่ต้องทำ — เติมผู้เรียก 5 จุด:**

| ระบบ | ไฟล์ · จุดเสียบ | เรียก |
|---|---|---|
| เก็บของธรรมชาติ | `Player.Gathering.cs:357` หลัง `AddItems(items);` | `AddExpForAction(SkillTuning.GatherWeight, SkillCat.Gathering, $"เก็บ {spec.Id}")` |
| ชำแหละซาก | `Player.Gathering.cs` สาขา `carcass != null` (จุดที่ตั้ง `Butchered = true`) | `AddExpForAction(SkillTuning.ButcherWeight, …, "ชำแหละ")` |
| คราฟต์สำเร็จ | `Player.Crafting.cs` ตรงที่ส่ง `Crafted` แบบสำเร็จ | `AddExpForAction(SkillTuning.CraftWeight, …, $"คราฟต์ {recipe.id}")` |
| สร้างเสร็จ | `Player.Building.cs:607` หลัง `SetBuildingState(..., Completed, null)` | `AddExpForAction(SkillTuning.BuildWeight, …, $"สร้าง {bp.Id}")` |
| ล่าสัตว์ตาย | `Player.Hunting.cs` จุดที่สัตว์ตาย (คนกัดคือผู้เล่นคนนี้) | `AddExpForAction(SkillTuning.KillWeight, …, "ล่า")` |

⚠️ **หมวดสกิล (`SkillCat`) ต้องเลือกจากของจริง ไม่ใช่เดา** — `Shared.Skill.Category` มีค่าอะไรบ้างให้เปิดดูที่
`server/GameCode/Shared.Skill/Category.cs` และเทียบกับ `category` ของโหนดใน `data/assets/skill/skills.json`
(เช่นหมวด `7` = gathering) ถ้าจับคู่ไม่ได้ให้ส่ง `null` ไปก่อนแล้วเขียนคอมเมนต์ว่าทำไม

⚠️ **อย่าเซฟซ้ำ** — `AddExp` เรียก `SaveSkillState()` ให้แล้ว และ `OnContextChanged` เขียนไฟล์ `.player` ทั้งไฟล์ทุกครั้ง
(`Core/GameServer.cs:186-194`) การกระทำหนึ่งครั้งต้องเขียนไฟล์ครั้งเดียว

**วิธียืนยัน:** เปิดเซิร์ฟ เก็บของ 40 ครั้ง แล้วดู log ต้องขึ้น
`[skill] xxxxxxxx เลเวล 1 → 2 (exp NNN, จาก เก็บ ...)` และแถบ exp ในเกมต้องขยับ

## 1.2 สูตรคราฟต์ปลดหมดตั้งแต่นาทีแรก

**หลักฐาน:** `server/Core/Player.Crafting.cs:357` `SendRecipes()` ส่ง `CraftRecipeStore.CraftableIds()`
คือ **625 สูตรทั้งหมด** พร้อมคอมเมนต์ยอมรับเองว่าเป็นทางลัดเพราะตอนนั้น `GetSkills` ยังตอบชุดว่าง

แต่ตอนนี้ `Player.Skills.cs` ทับ `GetSkills` ด้วยของจริงแล้ว ⇒ **เงื่อนไขที่ทำให้ต้องลัดหายไปแล้ว**

**ข้อมูลจริงพร้อมใช้ 100% (ตรวจแล้ว):**

```
data/assets/skill/skills.json   โหนดสกิล → "rewards": ["blade_stone"]
data/assets/skill/rewards.json  1,321 รายการ — 604 รายการมี "recipe_ids"
   ตัวอย่าง: "blade_stone": { "type": 2, "sub_skill_category": 14, "recipe_ids": ["blade_stone"] }
```

ฝั่งเกมใช้เส้นเดียวกัน: `client/Crafting/Recipe.cs:99` `reward.RecipeIds.Contains(Id)` ใน `GetOwnerSkill()`

**สิ่งที่ต้องทำ:**

1. เพิ่มฟิลด์เดียวใน `SkillRewardJson` (`Player.Skills.cs:160`):
   ```csharp
   /// <summary>สูตรที่รางวัลนี้ปลดล็อก (type 2 — 604/1,321 รายการมีช่องนี้)</summary>
   [JsonProperty("recipe_ids")] public string[] RecipeIds;
   ```
   ตัวโหลดมีแล้ว: `Player.Skills.cs:338` `Rewards = Json.ReadFromFile<Dictionary<string, SkillRewardJson>>("skill/rewards")`
2. เขียนเมธอดรวม "สูตรที่ผู้เล่นคนนี้ปลดแล้ว" = วนโหนดสกิลที่ **เรียนแล้ว** → `Rewards` → `RecipeIds`
3. `SendRecipes` ส่งเฉพาะ `intersect(CraftableIds(), สูตรที่ปลดแล้ว)`

⚠️ **ต้องเช็คก่อนปล่อย** — อาชีพตอนสร้างตัวละครแจกสกิลเริ่มต้นให้ (`data/assets/player/jobs.json` → `given_skills`
อ่านเข้ามาแล้วที่ `JobJson.GivenSkills` `Player.Skills.cs:194`)
**ถ้าสกิลเริ่มต้นไม่ปลดสูตรอะไรเลย ผู้เล่นใหม่จะคราฟต์อะไรไม่ได้เลยสักอย่าง = พังหนักกว่าเดิม**
ต้องรันเช็คก่อนว่าอาชีพทั้ง 8 ได้สูตรเริ่มต้นกี่สูตร ถ้าเป็น 0 ให้เปิดสูตรพื้นฐานชุดเล็กเพิ่มแล้วเขียนกำกับว่า `**ค่าของเรา**`

**เกี่ยวข้องกับบั๊กที่ผู้เล่นแจ้ง:** ใบเทส 6 ก.ย. ข้อ 4 *"ใบมีดหินเริ่มต้น คราฟไม่ได้"* — `blade_stone`
คือสูตรตัวอย่างข้างบนพอดี ให้ไล่ดูด้วยว่าคราฟต์ไม่ได้เพราะอะไรกันแน่ (ขาดวัสดุ · ขาดโต๊ะ · หรือ handler)

**วิธียืนยัน:** สร้างตัวละครใหม่ → หน้าคราฟต์ต้องมีสูตรจำนวน "น้อยแต่ไม่ใช่ศูนย์" → เรียนสกิลหนึ่งโหนด → สูตรใหม่ต้องโผล่เพิ่ม

# 🟠 ลำดับ 2 — ต้องทำก่อนเปิดเบต้า

## 2.1 อัปเซิร์ฟขึ้น VPS

VPS **ยังรัน build ของ opencode** ⇒ ไม่มีภาษาไทย · ไม่มีช่องโหว่ที่อุดไป · ไม่มี handler ทั้ง 399 ตัว
ยืนยันได้ด้วยการ grep หา `MoCatalog` / `HasStoredItems` / `FindOverlapping` ในไบนารีบน VPS = 0

ต้องคืน `run.sh` ที่มี `--download-url` ด้วย (เคยถูก `sed` ใส่ `\n` ตัวอักษรจนพังมาแล้ว 2 รอบ — เขียนทั้งไฟล์ด้วย heredoc)

## 2.2 commit

ตอนนี้ **75 ไฟล์เปลี่ยน + ลบ `Opencode/` 5,281 ไฟล์ ยังไม่ commit สักครั้ง** บน `main`
เช็ค `git branch --show-current` ก่อนเสมอ (เคยทำงานผิด branch มาแล้ว)

## 2.3 เทส handler 216 ตัวที่ไม่เคยถูกยิงจริง

build ผ่านไม่ได้แปลว่าทำงาน — เปิดเกมกดทุกเมนู แล้วดู 2 อย่าง:
- log เซิร์ฟต้องไม่มี `[conn] ไม่มี handler สำหรับ type=...`
- `%USERPROFILE%\AppData\LocalLow\NEXON Korea\Durango_ Wild Lands\output_log.txt` ต้องไม่มี exception ใหม่

⚠️ ~160 จาก 216 ตัวตอบ `Abort` "ยังไม่เปิดใช้งาน" — **นั่นถูกต้องตามที่ตั้งใจ** (กัน UI ค้าง ไม่ใช่ว่าฟีเจอร์ทำงาน)
สิ่งที่ต้องหาคือตัวที่ *ควร* ทำงานแล้วไม่ทำ

## 2.4 เอา BotBridge ออกจากชุดแจก

`client/BotBridge.cs` เป็นช่องโกงเต็มรูปแบบ (เสกของ/วาร์ป/อ่านสถานะ) — เปิดจริงต้องเอาออก
ตอนนี้เปิดด้วย env `DURANGO_BOT=1` เท่านั้น แต่โค้ดยังอยู่ในไฟล์ DLL ที่แจก

## 2.5 `game/account.key` ต้องไม่หลุดไปกับชุดแจก

**เคยหลุดมาแล้วจริง** — เป็นกุญแจประจำเครื่องของคนแพ็ก ใครโหลดไปจะเข้าตัวละครเดียวกันหมด
`tools/pack-vps.ps1` ใส่ `/XF 'account.key'` ไว้แล้ว **ห้ามเอาออก** — และตอนนี้ `game/account.key` โผล่มาอีก ต้องเช็คก่อนแพ็กทุกครั้ง

# 🟡 ลำดับ 3 — บั๊กและความเสี่ยงที่ค้าง

## 3.1 สัตว์ยืนนิ่งแต่ผู้เล่นโดนดาเมจ (ใบเทส 6 ก.ย. ข้อ 5)

ฝั่งเกมแพตช์ไปแล้ว **งานที่เหลือเกือบทั้งหมดอยู่ฝั่งเซิร์ฟ** — ห่วงโซ่หลักฐานครบใน
[แก้ฝั่งเซิร์ฟ-อนิเมชั่นสัตว์.md](แก้ฝั่งเซิร์ฟ-อนิเมชั่นสัตว์.md)

สรุปสั้น: ดาเมจกับอนิเมชั่นเป็นคนละสาย
- `Player.Hunting.cs` → `AnimalTurn` (~118-172) ส่ง `Effects = DamageEffects.None` · **ไม่ส่ง `Move` ท่าโจมตี** · **ไม่ส่ง `CombatInteraction`**
- อนิเมชั่นสัตว์ป่าฝั่งเกมขับด้วย `Move.MotionName` อย่างเดียว · `AnimalBehavior.Update()` ไม่เลือกท่าเอง
- `Support/AnimalMotions.cs` มีแค่ 9 คีย์ (Stand/Idle/Move/Eat/Alert/Dead/BattleStand/Groggy/Blow) — **ไม่มีท่าโจมตี**

## 3.2 บั๊กจากใบเทสที่ยังไม่ยืนยัน

| # | อาการ | สถานะ |
|---|---|---|
| 1-3 | ต้นไม้/กอหญ้า/หิน เก็บได้ชิ้นเดียว | แก้แล้ว (เก็บทีละ generator) **รอยืนยันในเกมรอบสอง** |

## 3.3 ความเสี่ยงที่ลดระดับไว้ ยังไม่ปิด

## 3.4 สาย radiotower ไม่เคยต่อติด

⇒ handler ลงทะเบียนไว้ก็ยังไม่มีทางถูกเรียก

## 3.5 ค่าที่เก็บแค่ในหน่วยความจำ (ล็อกเอาต์แล้วหาย)

- สวิตช์แจ้งเตือนช่องแชทเผ่า (`Player.Clan.cs` `_clanChannelNotifications`)
- `SetPersonalRegionAdmission` (`Player.Estate.cs`)

ทั้งคู่ต้องเพิ่มฟิลด์ใน `server/Core/PlayerContext.cs`

## 3.6 `Keepalive`(254) ไม่มี handler

ฝั่งเกมส่งทุก 30 วิแบบไม่รอคำตอบ (`client/Durango.Network/Connection.cs:216`)
ไม่กระทบอะไร แค่ log ขึ้นเตือน — ลงทะเบียน handler เปล่าไว้ได้ถ้าอยากให้ log สะอาด
