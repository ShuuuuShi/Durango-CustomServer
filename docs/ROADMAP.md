### A. ไม่มีระบบบัญชี/ตัวตนผู้เล่นเลย (9 ข้อ · ต้นตอเดียวกัน) — หนักที่สุด

`server/Core/Gateway.cs:236` `POST /accounts` แจกรายชื่อ**ตัวละครทุกตัวบนเซิร์ฟ**ให้ใครก็ได้
โดยไม่ตรวจอะไรเลย แล้วหน้าเลือกตัวละครในเกมเอามาทำเป็นปุ่มกดเข้าเล่นได้ตรง ๆ

* **ผู้เล่นคนที่ 2 เปิดเกมจะเห็นตัวละครของคนที่ 1 ในสล็อตตัวเอง กดเข้าเล่นได้เลย**
  ไม่ต้องแฮก ไม่ต้องใช้เครื่องมือ ไม่ต้องรู้อะไร — และตัวที่ "เพิ่งออกจากเกมล่าสุดของทั้งเซิร์ฟ"
  ถูกตั้งเป็น recommended ให้อัตโนมัติด้วย (`client/Durango.Logic.Clusters/Account.cs:34`)
* `GET /entry?entity_id=` ย้าย session token ไปชี้ตัวละครไหนก็ได้ (`Gateway.cs:177-182`)
  ⇒ **curl 2 บรรทัดยึดตัวละครใครก็ได้** — ด่าน Auth ที่เอกสารนี้เคยเขียนว่า "อุดไว้แล้ว ห้ามถอย"
  จริง ๆ ถูกเปิดทางอ้อมให้ข้ามได้อยู่ดี
* `POST /sessions` เชื่อ entity id ที่ผู้ขอพิมพ์มาเอง · ใส่ id มั่ว ๆ = ได้ตัวละครสล็อตแรกไปเล่น
  (`GameServer.cs:133-141` fallback `_playerCtx` — มรดกจากเซิร์ฟ offline คนเดียว)
* `POST /players` ไม่ต้องมี token ก็เขียนทับตัวละครสล็อตแรกและเปลี่ยน TerrainId ของโลกหลักได้

ต้นตอ: `client/Durango.System/Platform.cs:22` `NPSN => string.Empty` และไม่มีคลาสไหน override
⇒ `account_id` ที่ส่งมาว่างทุกเครื่อง · และ `grep account_id server/` = **0 hit**
ฝั่งเซิร์ฟไม่มีคำว่า "บัญชี" อยู่ในโค้ดเลยแม้แต่คำเดียว

### B. ไม่มีการเช็คเจ้าของเลยสักจุด (3 ข้อ)

* `DestructArtifact` — รื้อบ้านใครก็ได้ ไม่เช็คเจ้าของ ไม่เช็คระยะ (`Player.cs:1078`)
  entity id ได้มาฟรีจาก `AppearArtifact` ที่เซิร์ฟส่งให้ทุกคนที่เดินผ่าน ⇒ เขียนสคริปต์ล้างทั้งเกาะได้
* ตู้/คลัง — `GetWarehouse` → `PopItemsFromWarehouse` ขนของออกจากตู้คนอื่นได้จากทั่วเกาะ
* กรงฝึกให้เชื่อง — ปล่อยสัตว์คนอื่นทิ้ง/ขโมยสัตว์ที่เชื่องแล้วได้

### C. โกงได้โดยไม่ต้องโกง (4 ข้อ)

* **คำสั่ง `Cheat` เปิดให้ทุก connection** ไม่มีด่านตรวจสิทธิ์ (`Player.cs:107`) — ใครก็เป็น GM
* เสกของไม่จำกัดด้วย message ปกติ 2 ตัว: `Touch` ปลอม → `Collect` (ไม่ต้องใช้ Cheat เลย)
  `HandleTouchMsg` เชื่อ `touch.EntityType`/`touch.Tile` ที่ client ส่งมาล้วน ๆ ไม่เคยถามโลก
* **ชำแหละซากสัตว์ได้ไม่จำกัดครั้ง** — ผู้เล่นปกติกดรัวก็เจอเองในชั่วโมงแรก ไม่ใช่การโกง
* `SetStorageItem` ให้ client เขียนทับสถานะสกิลของตัวเองในไฟล์เซฟ ⇒ ตั้งเลเวลเองแม้ปิด cheat

### D. รับคนไม่ไหว (6 ข้อ) — ตัวเลขที่วัดจากโค้ดจริง

* **เสิร์ฟไฟล์ asset ผ่าน HTTP อยู่บน main loop เดียวกับที่เดินเกม** — 13 คนโหลดพร้อมกันเหลือ 2 TPS
  มือถือเน็ตช้าเครื่องเดียวก็ทำให้เกม**หยุดเดินทั้งเกาะ** (`file.CopyTo` บล็อกจนกว่า TCP จะระบาย)
* **Player/Connection รั่วถาวร 4.08 MB ต่อการต่อหนึ่งครั้ง** ไม่มีวันคืน
  เกมมือถือหลุด/กลับเข้าบ่อย 50 คน × 10 ครั้ง/วัน = **2 GB/วัน**
* `Move` ก้อนเดียวขนาด 512 KB **เตะทุกคนบนเกาะหลุดพร้อมกันในเฟรมเดียว** ทำซ้ำได้ไม่จำกัด
* เก็บของ 1 ครั้ง = เซฟไฟล์เกาะทั้งใบ + fsync บน main loop
* ไม่มีเพดาน/timeout ของ connection ที่ยังไม่ผ่าน Auth ⇒ เปิด TCP ค้างไว้เฉย ๆ ก็ทำ RAM หมดได้
* `--max-players 50` กันได้แค่ประตูหน้า (HTTP) ทางเข้าจริง (TCP) ไม่มีเพดานเลย

### E. เปิดแล้วดูแลไม่ได้ (ที่เหลือ)

* **ไม่มีเครื่องมือเตะ/แบน/ปิดปากเลยสักตัว** — เจอคนป่วนทำได้อย่างเดียวคือปิดทั้งเซิร์ฟ
  (และต่อให้เขียน "แบน" ก็ไม่มีความหมาย เพราะไม่มีบัญชีให้แบน — ดูข้อ A)
* ไม่มีสวิตช์ปิดปรับปรุง/ประกาศถึงผู้เล่น · ไม่มีตัวเฝ้า/alert เวลาเซิร์ฟล่ม
* `/knock` ตอบ `compatible = true` ตายตัว ไม่เคยอ่าน `?version=` ⇒ เกมเวอร์ชันเก่าต่อเข้ามาได้
  แล้วค่าที่ unpack เพี้ยนถูกเขียนลงไฟล์เซฟเงียบ ๆ · และทุก build รายงานตัวเองว่า `5.2.1` เหมือนกันหมด

### ลำดับที่ควรทำถ้าจะเปิดเบต้าจริง

1. **ระบบบัญชี** (A) — ใหญ่สุด ~1 สัปดาห์ แต่ถ้าไม่มี ข้ออื่นแทบไม่มีความหมาย
   (แบนใครไม่ได้ · รู้ไม่ได้ว่าใครก่อเรื่อง · เจ้าของก็ระบุไม่ได้)
2. **ปิด Cheat + เช็คเจ้าของ** (B, C) — ส่วนใหญ่เป็นงานหลักชั่วโมง ทำได้เร็ว
3. **ย้าย HTTP ออกจาก main loop + อุด Connection รั่ว** (D) — ไม่งั้นคนเข้าพร้อมกันเกิน ~10 คนไม่ได้
4. **เครื่องมือแอดมิน** (E) — เตะ/แบน/ประกาศ/ปิดปรับปรุง

ระหว่างนี้ที่เปิดอยู่บน VPS ใช้ได้ในฐานะ **เซิร์ฟทดสอบวงปิดกับคนที่ไว้ใจได้เท่านั้น**

## ข้อควรระวัง (บทเรียนจากโปรเจกต์เดิม)

1. **อย่าเดาแล้วเขียนมั่ว** — ไม่รู้ว่า field ไหนหมายถึงอะไร ให้ดู `client/` ว่าอ่านค่าไปทำอะไร
   โปรเจกต์เดิมเคยถอยงานสกิลทั้งชุด 3 รอบเพราะตั้งเกณฑ์ปลดล็อกเอง
2. **1 packet ต่อ 1 เฟรม** — `Connection.ProcessPacketQueue()` dequeue แค่ packet เดียวต่อรอบ
   คนเล่นเยอะจะหน่วง ต้องแก้ตอนขยาย
3. **buffer 12 MB ต่อผู้เล่น** — `Connection.cs` จอง static (2 MB × 6) · 100 คน = 1.2 GB ต้องทำ pool
4. **`Auth` ผูก token จาก `/sessions`** — `Core/GameServer.cs:122-131` อุดไว้แล้ว **ห้ามถอย**
   ต้นฉบับเชื่อ `EntityId` ที่ client ส่งมาตรง ๆ = สวมรอยใครก็ได้
5. **bind wildcard ต้อง urlacl** — ให้เครื่องอื่นเข้าได้ ต้องรันครั้งเดียวแบบ admin:
   `netsh http add urlacl url=http://*:8190/ user=Everyone` ไม่งั้นตกไป loopback (log บอกเอง)
6. **exp กู้ไม่ได้** — ข้อมูลเกมตั้ง `exp_amount` ของสัตว์ทุกตัวเป็น 0 ตัวเลขจริงอยู่ฝั่งเซิร์ฟ NEXON
   ต้องตั้งเอง ⇒ ตั้งไว้ที่เดียวใน config ปรับได้ ไม่กระจายใน code
