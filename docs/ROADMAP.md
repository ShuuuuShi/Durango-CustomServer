### ✅ D. รับคนไม่ไหว (6 ข้อ) — **ปิดแล้ว** (`c64fee6` + `87a5510`)

อุด Connection รั่ว (เก็บ delegate ไว้ถอดได้) · เพดานสาย TCP + ตัดสายที่ไม่ผ่าน Auth ใน 30 วิ ·
จำกัดขนาดก้อน `Move` · ย้ายการเสิร์ฟไฟล์ออกจาก main loop (ThreadPool จำกัด 8 พร้อมกัน)

⚠️ เส้น `FileResponse` (assetbundle) **ยังไม่ได้เทสตรง ๆ** เพราะไม่มีไฟล์ bundle ในเครื่องพัฒนา
ต้องเทสอีกครั้งบน VPS ที่มีของจริง

<details><summary>รายละเอียดเดิม</summary>


* **เสิร์ฟไฟล์ asset ผ่าน HTTP อยู่บน main loop เดียวกับที่เดินเกม** — 13 คนโหลดพร้อมกันเหลือ 2 TPS
  มือถือเน็ตช้าเครื่องเดียวก็ทำให้เกม**หยุดเดินทั้งเกาะ** (`file.CopyTo` บล็อกจนกว่า TCP จะระบาย)
* **Player/Connection รั่วถาวร 4.08 MB ต่อการต่อหนึ่งครั้ง** ไม่มีวันคืน
  เกมมือถือหลุด/กลับเข้าบ่อย 50 คน × 10 ครั้ง/วัน = **2 GB/วัน**
* `Move` ก้อนเดียวขนาด 512 KB **เตะทุกคนบนเกาะหลุดพร้อมกันในเฟรมเดียว** ทำซ้ำได้ไม่จำกัด
* เก็บของ 1 ครั้ง = เซฟไฟล์เกาะทั้งใบ + fsync บน main loop
* ไม่มีเพดาน/timeout ของ connection ที่ยังไม่ผ่าน Auth ⇒ เปิด TCP ค้างไว้เฉย ๆ ก็ทำ RAM หมดได้
* `--max-players 50` กันได้แค่ประตูหน้า (HTTP) ทางเข้าจริง (TCP) ไม่มีเพดานเลย

</details>

## ข้อควรระวัง (บทเรียนจากโปรเจกต์เดิม)

1. **อย่าเดาแล้วเขียนมั่ว** — ไม่รู้ว่า field ไหนหมายถึงอะไร ให้ดู `client/` ว่าอ่านค่าไปทำอะไร
   โปรเจกต์เดิมเคยถอยงานสกิลทั้งชุด 3 รอบเพราะตั้งเกณฑ์ปลดล็อกเอง
2. **1 packet ต่อ 1 เฟรม** — `Connection.ProcessPacketQueue()` dequeue แค่ packet เดียวต่อรอบ
   คนเล่นเยอะจะหน่วง ต้องแก้ตอนขยาย
3. **buffer 12 MB ต่อผู้เล่น** — `Connection.cs` จอง static (2 MB × 6) · 100 คน = 1.2 GB ต้องทำ pool
4. **`Auth` ผูก token จาก `/sessions`** — `Core/GameServer.cs:122-131` อุดไว้แล้ว **ห้ามถอย**
   ต้นฉบับเชื่อ `EntityId` ที่ client ส่งมาตรง ๆ = สวมรอยใครก็ได้
5. **bind wildcard ต้อง urlacl** — ให้เครื่องอื่นเข้าได้ ต้องรันครั้งเดียวแบบ admin:
   `netsh http add urlacl url=http://*:8190/ user=Everyone` ไม่งั้นตกไป loopback (log บอกเอง)
6. **exp กู้ไม่ได้** — ข้อมูลเกมตั้ง `exp_amount` ของสัตว์ทุกตัวเป็น 0 ตัวเลขจริงอยู่ฝั่งเซิร์ฟ NEXON
   ต้องตั้งเอง ⇒ ตั้งไว้ที่เดียวใน config ปรับได้ ไม่กระจายใน code
