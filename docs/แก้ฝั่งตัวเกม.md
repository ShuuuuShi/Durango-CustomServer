# รายการแก้ไขฝั่งตัวเกม (client/)

ไฟล์ใน `client/` คือซอร์สที่ถอดออกมาจาก `Assembly-CSharp.dll` ของ NEXON แล้วคอมไพล์กลับ
ทุกครั้งที่แก้ต้องจดไว้ที่นี่ว่า **แก้อะไร · เพราะอะไร · หลักฐานอะไร**
(กฎเหล็กเรื่อง "ห้ามแก้ไฟล์ต้นฉบับ" ใช้กับ `server/GameCode/**` ซึ่งเป็นโปรโตคอล — ไม่รวมไฟล์ในนี้)

วิธี build: `dotnet build client -c Release` แล้วก๊อป
`client/bin/Release/net35/Assembly-CSharp.dll` → `game/Durango_Data/Managed/`
(ต้องปิดเกมก่อน ไม่งั้นไฟล์ถูกล็อก)

## 6 ก.ย. 2026 — `InputKeyboard.cs`

**อาการ:** ค้างหน้าโหลดไม่เข้าเกม (ม่านโหลดไม่เปิด) HUD พัง NRE รัวทุกเฟรม

**หลักฐาน:** `output_log.txt` — exception แรกสุดของ session อยู่ที่บรรทัด 47 ตั้งแต่ยังอยู่หน้าไตเติล

```
ArgumentException: RenderTextureDesc width must be greater than zero
  at Durango.UI.FogOfWarCover.Initialize / MapContext.ApplyTerrainMeta / MapContext.OnAwake
  UIManager:InitUIGroups()  ←  UIManager:FindScript()  ←  MenuHelper:GetScript(MenuType)
  ←  InputKeyboard:Process()  ←  InputSystem:Update()
```

แล้วพังต่อกันเป็นทอด: `WeatherManager.OnAwake` · `ClanLevelPage.Init` · `EventCalendarWidget.Init`
สุดท้ายพอเข้าฉากจริง `TerrainBase` ไม่เคยถูกสร้าง:

```
Can't add script behaviour TerrainBase. The script class can't be abstract!
NullReferenceException
  at Singleton<TerrainBase>.Instance ()
  at Durango.UI.LoadingCurtainBase+<WaitForChunkLoading>.MoveNext ()
```

โครูทีนที่รอ chunk ตายกลางคัน ม่านโหลดจึงไม่ถูกสั่งเปิด = ค้างหน้าโหลดถาวร
(NRE รัวทุกเฟรมของ `MapIndicators` · `MoveTrail` · `FatigueGaugeScrollSprite` เป็นผลพวง ไม่ใช่เหตุ)

**ต้นเหตุ:** ปุ่มลัดเมนูของ PC (`InputKeyboard.InitShortcut`) เรียก `MenuHelper.GetScript(menuType)`
ซึ่งไปเรียก `UIManager.FindScript()` → `Singleton<UIManager>.Exist()` → **สร้าง UIManager ขึ้นมาเอง**
ถ้ากดตอนยังอยู่หน้าไตเติล `InitUIGroups()` จะสร้าง prefab ของ UI ในเกมทั้งชุด
ตอนที่ terrain/สภาพอากาศยังไม่มี → เกมพังยาวตั้งแต่ก่อนเข้าฉาก
เป็นบั๊กเฉพาะ PC (มือถือไม่มีคีย์บอร์ด) และมีอยู่เดิม ไม่ได้เกิดจากแพตช์ของเรา

**แก้:** ใส่ยามหน้าปุ่มลัด — ถ้า `Singleton<UIManager>.HasInstance()` เป็น false ให้ return ทันที
ปุ่มลัดจะทำงานเฉพาะตอนเข้าเกมแล้วจริง ๆ และไม่เป็นคนสร้าง `UIManager` เอง
(รูปแบบนี้มีใช้อยู่แล้วในโค้ดต้นฉบับ เช่น `ConfigInstance.cs:314`, `BlueprintTodoCollection.cs:36`)

## 6 ก.ย. 2026 — `Durango.UI/ExpectResultWidget.cs`

**อาการ:** กดที่หลุมก่อสร้างแล้วหน้าต่างใส่วัสดุไม่เด้งขึ้นมาเลย (บั๊กข้อ 6 ในชุดทดสอบ)
วงล้อโหลดค้างอยู่ ไม่มีข้อความ error ให้ผู้เล่นเห็น

**หลักฐาน:** `%USERPROFILE%\AppData\LocalLow\NEXON Korea\Durango_ Wild Lands\output_log.txt`
เจอ `NullReferenceException` 8 ครั้ง จุดเดียวกันทั้งหมด:

```
NullReferenceException
  at Durango.UI.ExpectResultWidget.Set (BuildSlotContainer slotContainer)
  at Durango.UI.CraftGroupBase.SetSlotContainer (SlotContainer, Boolean)
  at Durango.UI.CraftGroupBase.Open (BuildSlotContainer, ...)
  at Durango.UI.CraftGroupBase.System_ArtifactOccupied ()
  at BuildSystem.<RequestArtifactMaterials>b__0 (ArtifactMaterials, PacketHeader)
```

อ่านจากล่างขึ้นบน: เซิร์ฟตอบ `ArtifactMaterials` ถูกแล้ว → event `ArtifactOccupied` ยิงแล้ว →
`Open()` ถูกเรียกแล้ว → **ระเบิดกลางทางที่ `ExpectResultWidget.Set`** → `Open()` ไม่จบ หน้าต่างจึงไม่โผล่

ฝั่งเซิร์ฟไม่ผิด — log เซิร์ฟตอนเดียวกันขึ้นครบ:
`[สร้าง] ce5a5a1e เปิดหลุม s02_bonfire ที่ [43,50] state=Occupied ช่องแบบแปลน=1 วัสดุที่ใส่แล้ว=0 กลุ่ม`

**ต้นเหตุ:** ตัวเกมมี UI สองชุด — มือถือใช้ `CraftGroup` (มีฟิลด์ `_mainLayout`,
`_recipeStepSelectHorizontalWidget` เพิ่ม) ส่วน PC ใช้ `CraftGroup_PC` ซึ่งเป็น **คลาสว่าง**
สืบจาก `CraftGroupBase` เฉย ๆ (ในโปรเจกต์มีคลาส `*_PC` แบบนี้ 45 ตัว)
prefab ฝั่ง PC จึงผูกวิดเจ็ตไม่ครบเท่าของมือถือ ฟิลด์ `[SerializeField]` ที่ไม่ถูกผูกจะเป็น `null`
โค้ดเดิมอ้างฟิลด์พวกนี้ตรง ๆ (`_helpLabel.text`, `_remodelingWidget.gameObject`, …) เลย NRE

**แก้:** ในไฟล์นี้ทุกจุดที่อ้างวิดเจ็ตให้กัน `null` ก่อน ผ่านตัวช่วย `SetVisible` / `SetText`
รวม 20 จุด ครอบคลุม `OnStart`, `Set(CraftSlotContainer)`, `Set(BuildSlotContainer)`,
`Refresh`, `ClearEstimation`, `UpdateLayout`, `SetIconMode`, `SetPreviewTextureMode`,
`SetCraftEstimation`, `SetBuildEstimation`, `SetRemodelingEstimation`,
`SetTechSupportEstimation`, `SetPreview`, `ShowHelpTooltip`
วิดเจ็ตที่ขาดเป็นแค่ป้ายและแผงเสริม (ป้ายหัวข้อ · แผงเปลี่ยนแบบบ้าน · ตัวเลือกจำนวน · ป้ายของแถม)
ข้ามได้ ไม่กระทบการใส่วัสดุและการกดสร้าง

เพิ่ม `ReportMissingWidgetsOnce()` — เขียน log ครั้งเดียวต่อวิดเจ็ตว่า prefab ตัวไหนขาดฟิลด์อะไรบ้าง
ไว้ไล่ปัญหา UI ฝั่ง PC ตัวอื่นต่อ (ดูใน `output_log.txt` คำว่า `[ExpectResultWidget]`)

**ผลพลอยได้:** เส้นทาง craft (`Set(CraftSlotContainer)`) ใช้วิดเจ็ตชุดเดียวกัน จึงได้รับการกันไปด้วย
— น่าจะเกี่ยวกับบั๊กข้อ 4 "ใบมีดหินเริ่มต้น คราฟไม่ได้" ต้องเทสยืนยันอีกที

## 7 ก.ย. 2026 — บังคับโปรล็อกสอนเล่นสำหรับตัวใหม่

**เป้าหมาย:** ตัวละครใหม่ต้องลงจากรถไฟ + โหมดสอนเล่น/หมานำทาง ตามต้นฉบับ

**จุดที่ตัดโปรล็อกได้:**
1. `PlayerSelectionGroup` ถาม "ข้ามโปรล็อกไหม" แล้วตั้ง `ToBeSkipped`
2. `TitleMenuUserControlBase.OnConfirm` เลือกตัวเก่าอัตโนมัติถ้ามี
3. `PrologueManager` เคารพ `ToBeSkipped` / `DeveloperSettings.SkipPrologue`

**แก้:**
- สล็อตว่าง → `CreateNewPlayer(false)` เสมอ ไม่ถามข้าม
- `CreateNewPlayer` บังคับ `ToBeSkipped=false` + เคลียร์ `skip_prologue`
- Confirm สล็อตว่าง → `PlayerId=null` เพื่อเข้า `FadeOutPrologue`
- ตอนเข้าฉาก Prologue ถ้ายังไม่มี PlayerId ให้เคลียร์ธงข้าม

**วิธีเทส:** เลือกสล็อตว่าง/สร้างตัวใหม่ → ต้องเข้าฉาก Prologue ไม่เด้งเข้าเกาะทันที
