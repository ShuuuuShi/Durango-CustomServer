# สถาปัตยกรรมเซิร์ฟเวอร์ Nexon / What Studio (Durango)

สรุปจากงานพูด NDC ของ **이흥섭 (Heungsub Lee)** — Vol.1–3 และโน้ตชุมชน  
ใช้เป็น **แนวทางสเกล** ไม่ใช่สเปกที่ LastHuman ต้องทำทันที

## เป้าหมายเดิม
- โลกถาวร · ช่องทางเดียว (ไม่แยกชาแนลในพื้นที่เดียวกัน)
- ไม่มี SPOF · ขยายแนวนอน · พื้นที่เกือบไม่จำกัดด้วยการเพิ่มเกาะ

## บทบาทโหนด
| โหนด | หน้าที่ |
|---|---|
| Frontend | คลายเอนต์ต่อ · สตรีมสถานะผู้เล่น |
| Gateway | ล็อกอิน / จัดสรร frontend |
| Zoo | จำลองสัตว์ |
| Garden | วัตถุนิ่ง (พืช แร่ สิ่งปลูกสร้าง) |
| Colosseum | ห้องต่อสู้ + แผนจังหวะโจมตี |

## เทคนิคหลัก
- P2P ระหว่างโหนด + สมุดที่อยู่ **etcd** (เคยใช้ ZeroMQ)
- โลกแบ่ง **chunk** · ซิงก์ Pub/Sub · ผู้เล่นต่างโหนดเป็น **ghost**
- **เอกสารดิน** ต่อ chunk ใน **Couchbase**
- ธุรกรรมหลายเอกสารแบบ **BASE** + ล็อก chunk TTL
- **Mirage LOD**: ธรรมชาติ/สัตว์ hydrate เมื่อมีผู้เล่นใกล้
- ขยายความจุด้วย **เพิ่มเกาะ** + ตัวกระจายประชากรตอนเดินทาง
- Infra: **AWS** · Terraform · Packer · Ansible · rolling update

## บทเรียนเปิดบริการ
- เกาะแน่น / คิวล็อกอิน (MySQL → Redis) / Couchbase index ร้อน
- ฝันเซิร์ฟเดียวพัง → เปิดหลายเซิร์ฟ แล้วค่อยรวม
